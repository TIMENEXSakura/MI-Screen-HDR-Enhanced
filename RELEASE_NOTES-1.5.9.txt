小米截屏HDR增强 1.5.9 Release
MI Screen HDR Enhanced · versionCode 159

新增与修复

- RGB 增益保留：分别保留红、绿、蓝通道的增益信息，成功取得 RGB 时优先保留增益图，跳过像素重分配，并使用质量 100 的 JPEG 4:4:4 编码。
- 分级读取回退：RGB 读取或校验失败后，先使用同一张高精度画面尝试普通精准读取；若同帧普通读取也失败，重新获取系统原始截图并尝试其增益图的普通像素精准处理；这一步也失败，才保留未经精准处理的系统截图。关闭 RGB 时直接尝试普通精准读取。回退不会更改用户开关。
- 截屏诊断：区分单通道、三个通道数值相同以及真正包含 RGB 差异的增益图；分别记录 RGB 与普通读取失败原因，并支持导出最近的截屏记录。
- 安装时检查 persist.sys.support_ultra_hdr：已为 true 时保持原值，缺失或未开启时写入持久属性 true，并读取回来确认。失败会显示原因，不会报告安装成功。
- 只生成或导出 ZIP 时不更改本机属性；离线包在目标设备实际安装时才进行上述检查。
- 正式模块 ID：生成包改为 mi_screen_hdr_enhanced；安装验证通过后停用旧的 xiaomi17u_hdr_clamp_test 和 hdr_screenshot_tonemap（含待更新副本），保留旧备份，避免重复挂载。使用 Mountify 手动选择时需将新 ID 加入选择列表。
- 升级与还原：支持从旧版仅亮度补丁升级，修补版与原厂备份需通过完整往返校验；继续保留启动验证与异常停止挂载。
- 保留 HDR 预览、裁切、带壳保存、流动辉光和亮度比例等已有功能。中性标准增益参数不会仅因屏幕亮度比例被强行当作有效 HDR。

实验性功能

- 底层 RGB 增益生成：对完整库指纹已验证的小米实现，使用系统同一帧的线性 SDR/HDR 数据计算逐通道增益。当前审查基于小米 17 Ultra 的特定系统库；其他构建会明确报告 RGB 不支持，不按固定地址盲目修改。
- 特殊 HDR 取帧：“匹配屏幕颜色”和“兼容取帧”使用高精度画面尝试重建增益，默认仍为系统取帧。此选项与 RGB 保留开关分开，可增加截图耗时和内存使用。
- 系统录屏设置：整合录屏后端、输入帧等待时间、超时继续录屏和运行状态；Vulkan 为实验后端，输入图像与对应的同步信号配对，超时帧按设置跳过或结束录制。
- 系统合成后端切换：可选择支持的 GLES/Vulkan 后端，保留原设置恢复机制；此设置影响系统合成，需手动重启，实际支持取决于系统库及 Root 环境。

安装与验证

需要 Android 14 及以上 ARM64、小米系统截屏、Root，以及支持 API 102 的 LSPosed。
安装 APK 后启用模块，作用域选择小米截屏；需要录屏实验功能时同时选择小米屏幕录制。
在 APP 主页选择“安装与导出 → 自动识别并安装”，成功后手动重启手机加载底层模块。
更新 APK 不等于更新底层模块；升级本版请重新执行 APP 内的模块安装。

persist.sys.support_ultra_hdr 是持久系统设置，停用或卸载挂载模块不会自动撤销它。
开启此属性不代表设备具有全部 Ultra HDR 能力，也不保证完整捕获杜比、徕卡或其他私有 HDR 效果。
已丢失的 RGB 数据、未进入系统 HDR 输入的显示效果以及超出原生增益范围的信息不能靠此更新补回。

验证涵盖 CI 构建、安装/回退与属性开关测试，以及手机上的 GPU、增益图、JPEG 和分级回退测试。
实验性路径的实际效果仍需结合具体内容、固件和显示环境验证，不将合成测试等同于所有场景实测。
APK 由通过 CI 的同一提交产物签名，随 Release 提供源码、构建信息和校验值；不分发专有系统 SO。
